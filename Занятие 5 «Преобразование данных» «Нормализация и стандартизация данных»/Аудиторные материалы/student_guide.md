# Инструкция слушателю

## Что вы будете делать

В течение четырёх практических пар вы пройдёте путь от исходного CSV-файла до воспроизводимого набора признаков:

```text
исходные данные
→ преобразование типов
→ изменение формы таблицы
→ агрегация и объединение
→ аналитическая витрина
→ масштабирование
→ preprocessing для новых данных
```

Источник данных: [MoviesOnStreamingPlatforms.csv](https://github.com/Swapnajacontribution/Datasets/blob/main/MoviesOnStreamingPlatforms.csv).

Одна строка исходной таблицы описывает один фильм. Столбцы Netflix, Hulu, Prime Video и Disney+ содержат значения 0/1 и показывают, доступен ли фильм на соответствующей платформе.

## С чего начать

В каждом тематическом каталоге откройте:

```text
notebooks/student_practice.ipynb
```

Файл `teacher_solution.ipynb` содержит полное решение. Сначала выполните задания самостоятельно. Используйте решение после собственной попытки или по указанию преподавателя.

Не перемещайте notebook отдельно от каталогов `data` и `outputs`: код использует относительные пути.

## Вариант 1. Запуск в VS Code

### Подготовка

1. Установите Python 3.10 или новее.
2. Установите Visual Studio Code.
3. Установите расширения **Python** и **Jupyter**.
4. Откройте в VS Code весь каталог выбранной пары.

### Создание окружения

Откройте Terminal в VS Code.

Windows:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### Запуск notebook

1. Откройте `notebooks/student_practice.ipynb`.
2. Нажмите **Select Kernel** в правом верхнем углу.
3. Выберите Python из `.venv`.
4. Выполните первую ячейку.
5. Убедитесь, что найден CSV-файл и созданы пути к папкам.
6. После этого выполняйте ячейки строго сверху вниз.

## Вариант 2. Запуск в Google Colab

## Общие правила выполнения

1. Сначала прочитайте markdown-пояснение перед ячейкой.
2. Не меняйте имена исходных столбцов до ячейки, где выполняется переименование.
3. Не запускайте нижние ячейки до верхних.
4. Не удаляйте проверки `assert`: они помогают обнаружить ошибку в момент её появления.
5. Не перезаписывайте `data/raw/MoviesOnStreamingPlatforms.csv`.
6. После завершения проверьте папки `data/processed` и `outputs`.
7. Каждый аналитический вывод связывайте с конкретной таблицей, числом или графиком.

# Пара 1. Преобразование типов и изменение формы

## Основные действия

1. Загрузить исходный CSV.
2. Проверить размер, типы, пропуски и дубликаты.
3. Удалить технический столбец `Unnamed: 0`.
4. Переименовать поля.
5. Преобразовать рейтинг вида `98/100` в число.
6. Нормализовать возрастную маркировку.
7. Создать признаки:
   - `movie_age`;
   - `decade`;
   - `title_length`;
   - `platform_count`;
   - `availability_group`;
   - `rating_band`;
   - `age_min`.
8. Перевести платформенные столбцы в длинный формат через `melt`.
9. Выполнить обратную проверку через `pivot`.
10. Сохранить результаты.

## Что должно получиться

- `data/processed/movies_clean.csv` — одна строка на фильм;
- `data/processed/movies_long.csv` — одна строка на связь фильма с платформой;
- `outputs/data_quality_after.csv`;
- графики распределения возрастных категорий, рейтинга и числа платформ.

## Самопроверка

- [ ] Исходная таблица содержит 9515 строк.
- [ ] `movie_id` уникален.
- [ ] `rating_score` является числовым.
- [ ] `platform_count` находится в диапазоне 1–4.
- [ ] `movies_long.csv` содержит 9777 строк.
- [ ] Число строк длинной таблицы равно сумме единиц в платформенных полях.

# Пара 2. Агрегация и аналитическая витрина

## Основные действия

1. Загрузить `movies_long_checkpoint.csv` и справочники.
2. Рассчитать статистику по платформам через `groupby` и `agg`.
3. Построить диагностические графики.
4. Построить `pivot_table` «платформа × десятилетие».
5. Выполнить `stack` и `unstack`.
6. Объединить данные со справочниками через `merge`.
7. Проверить кардинальность и отсутствие потери строк.
8. Создать one-hot признаки через `get_dummies`.
9. Собрать аналитическую витрину.

## Что должно получиться

- `outputs/platform_summary.csv`;
- `outputs/movies_by_platform_and_decade.csv`;
- `outputs/movie_features_one_hot.csv`;
- `data/processed/movies_datamart.csv`;
- графики количества фильмов и рейтингов по платформам.

## Самопроверка

- [ ] Длинная таблица содержит 9777 строк.
- [ ] После `merge` число строк не изменилось.
- [ ] Все ключи платформ сопоставлены.
- [ ] `stack → unstack` возвращает исходную матрицу.
- [ ] Витрина содержит 167 строк.
- [ ] Одна строка витрины соответствует комбинации `platform × decade × age_rating`.

# Пара 3. Нормализация и стандартизация

## Основные действия

1. Выбрать содержательные числовые признаки.
2. Заполнить пропуски медианой только для технического сравнения scaler-объектов.
3. Вручную рассчитать Min–Max и Z-score на небольшом примере.
4. Применить:
   - `MinMaxScaler`;
   - `StandardScaler`;
   - `RobustScaler`.
5. Сравнить статистики до и после.
6. Построить гистограммы и boxplot.
7. Сравнить вклад признаков в расстояние между двумя фильмами.
8. Отдельно применить `Normalizer` к строкам.

## Важно

- Масштабирование не удаляет выбросы.
- Стандартизация не делает распределение автоматически нормальным.
- Идентификаторы не масштабируются.
- `Normalizer` работает по строкам, а scaler-объекты — по признакам/столбцам.

## Самопроверка

- [ ] После Min–Max минимум обучающей таблицы близок к 0, максимум — к 1.
- [ ] После StandardScaler среднее признаков близко к 0.
- [ ] После Normalizer L2-норма каждой строки близка к 1.
- [ ] Создан `scaled_movie_features.csv` на 9515 строк.
- [ ] Сохранены таблица сравнения и вклад признаков в расстояние.

# Пара 4. Воспроизводимый preprocessing

## Основные действия

1. Подготовить данные единой функцией.
2. Разделить каталог на историческую и новую части до обучения преобразователей.
3. Выделить числовые и категориальные признаки.
4. Собрать числовой pipeline:
   - медианное заполнение;
   - `StandardScaler`.
5. Собрать категориальный pipeline:
   - заполнение наиболее частым значением;
   - `OneHotEncoder(handle_unknown='ignore')`.
6. Объединить контуры в `ColumnTransformer`.
7. Выполнить `fit_transform` только для истории.
8. Выполнить `transform` для новой части.
9. Сравнить корректный `transform` с ошибочным повторным `fit`.
10. Проверить неизвестную категорию.
11. Сохранить pipeline и матрицы.

## Что должно получиться

- `data/processed/historical_movies_preprocessed.csv`;
- `data/processed/new_movies_preprocessed.csv`;
- `outputs/preprocessing_feature_names.csv`;
- `outputs/preprocessing_pipeline.joblib`;
- диагностические графики.

## Самопроверка

- [ ] Историческая часть содержит 8326 строк.
- [ ] Новая часть содержит 1189 строк.
- [ ] Историческая и новая матрицы имеют одинаковое число признаков.
- [ ] На новой части не выполняется повторный `fit`.
- [ ] Неизвестная категория не вызывает ошибку.
- [ ] Pipeline сохранён и может быть загружен повторно.
