# От разрозненных выгрузок к витрине активности пользователей

## Цель

Самостоятельно подготовить воспроизводимый процесс обработки данных: преобразовать типы и структуру таблиц, объединить источники, создать аналитические признаки, сравнить методы масштабирования и применить обученный preprocessing к новой выгрузке.

## Исходная ситуация

Вы работаете аналитиком цифрового сервиса. Команда продукта передала сведения о пользователях, широкую выгрузку месячной активности, справочник тарифов и новую порцию данных. Руководителю нужна единая витрина для сравнения активности, расходов, нагрузки на поддержку и удовлетворённости.

## Инструменты

- Python 3;
- Jupyter Notebook, VS Code или Google Colab;
- pandas и NumPy;
- matplotlib;
- scikit-learn;
- joblib.

## Исходные файлы

- `users.csv` — пользователи и их характеристики;
- `monthly_activity_wide.csv` — показатели за три месяца в широком формате;
- `tariffs.csv` — справочник тарифов;
- `new_users.csv` — новая выгрузка для применения готового preprocessing.

## Что нужно сделать

### 1. Загрузка и диагностика

1. Найдите корень проекта и загрузите четыре файла по относительным путям.
2. Выведите размеры таблиц и первые строки.
3. Проверьте типы, пропуски, дубликаты и уникальность ключей.
4. Сформируйте таблицу качества данных.

### 2. Преобразование данных

1. Преобразуйте `registration_date` в дату.
2. Нормализуйте написание регионов и сегментов.
3. Преобразуйте расходы и оценки из строкового формата в числовой.
4. Переведите широкую таблицу активности в длинный формат с помощью `melt`.
5. Выделите из названия столбца показатель и месяц.
6. Соберите таблицу уровня «один пользователь × один месяц» через `pivot_table`.
7. Покажите обратное преобразование части данных в широкий формат.

### 3. Объединение и создание витрины

1. Объедините активность с пользователями.
2. Добавьте справочник тарифов.
3. Используйте `validate` и `indicator` для контроля соединений.
4. Проверьте число строк до и после `merge`.
5. Создайте признаки:
   - `tenure_days`;
   - `minutes_per_session`;
   - `over_limit_minutes`;
   - `spend_vs_fee`;
   - `avg_sessions_3m`;
   - `low_satisfaction`;
   - `high_support_load`.
6. Постройте агрегированную витрину по сегментам и тарифам.

### 4. Графическая проверка

Постройте не менее четырёх графиков:

- распределение расходов;
- boxplot расходов по тарифам;
- среднее число сессий по тарифам;
- количество пользователей по сегментам;
- один дополнительный график по выбору.

Каждый график должен иметь название, подписи осей и краткую интерпретацию.

### 5. Нормализация и стандартизация

1. Выберите минимум пять количественных признаков.
2. Не включайте идентификаторы, даты и категориальные коды.
3. Вручную рассчитайте Min–Max-преобразование одного значения.
4. Вручную рассчитайте z-оценку одного значения.
5. Примените `MinMaxScaler`, `StandardScaler` и `RobustScaler`.
6. Сравните статистики до и после преобразований.
7. Объясните, какой метод предпочтительнее при выбросах.

### 6. Применение к новой выгрузке

1. Соберите числовой и категориальный контуры через `ColumnTransformer`.
2. Используйте `SimpleImputer` для числовых пропусков.
3. Используйте `OneHotEncoder(handle_unknown="ignore")` для категорий.
4. Выполните `fit` только на исторической витрине.
5. Примените `transform` к `new_users.csv`.
6. Сохраните итоговую матрицу признаков и preprocessing-объект.
7. Объясните, почему повторный `fit` на новой выгрузке нарушает сопоставимость.
